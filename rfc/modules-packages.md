# Lyra RFC：模块、包与构建

**状态：模块、版本解析与撤回、脚本授权边界已接受；清单字段、注册中心协议和沙箱实现仍开放。**  
**范围：** 源码模块、可见性、别名/re-export、包身份、依赖解析、锁文件、源码分发和第三方脚本。

## 模块与导入

- 每个包的 `src` 下，一个目录组成一个模块；同目录文件共享模块命名空间。
- 模块名从相对 `src` 的目录结构产生。把声明在同一目录的一个源文件拆分成多个文件不改变模块路径；移入另一目录会改变模块路径。
- 跨包导入从清单中的依赖简称起步，不从源文件路径起步。普通 `import` 只引入名称，不自动再导出，也不运行模块初始化、启动后台任务或执行 I/O。
- 模块间签名可相互引用。常量求值依赖环必须诊断；包依赖有环必须拒绝并输出依赖链。

```text
package-config/
  src/net/model.ly      // 公开类型 Endpoint
  src/net/defaults.ly   // 公开函数 localhost()，返回 Endpoint

import cfg.net.Endpoint
import cfg.net.localhost
```

导入使用 `import cfg.net.Endpoint`；示例文件名不构成模块身份，import 无运行时副作用。

## 可见性与公开别名

- 未显式公开的声明默认只在同一个模块中可见。
- `pub` 的具名声明可被其他模块导入；不另外引入本包级 `internal` 可见性层。
- 使用 `pub import cfg.net.Endpoint as PublicEndpoint` 显式 re-export，可重命名类型、函数和常量。
- 公共类型别名不是新类型，不改变被引用声明的身份。不能通过别名把私有类型提升为公开类型。
- 公开签名中的类型和结构约束也必须公开，包括容器、枚举载荷和函数类型的嵌套类型实参。编译器在原声明处检查；导出别名不会绕过检查。公开对象仍可有私有表示字段。
- [无名隐式转换](0003-types.md)只能在源类型或目标类型的定义模块声明。`pub implicit` 按类型对跨模块查找，不需要导入转换本身；通过别名或 re-export 使用类型，找到的仍是原类型的转换。
- 诊断优先使用调用点可见的别名，同时提供原始声明位置用于定位定义。
- workspace 同一开发环境中的包不会绕过公开可见性。
- [扩展方法](language-core.md)遵守相同边界：同模块可访问模块私有成员，外部模块不能通过给类型添加扩展来访问它们。

删除或改名公开名称（包括 re-export）按破坏性 API 变更处理，即使原始声明仍存在。宏生成声明的可见性处理见[元编程与数据交换](metaprogramming-data.md)。

## 包身份、解析和锁

包身份按“来源注册中心/来源 + 完整包名”确定；清单中的本地依赖简称只用于局部命名，不改变身份。包清单暂用 JSON5 设计，字段和锁文件格式尚未冻结。

一次最终构建图中，一个包身份只解析到一个版本。首版支持精确版本及 SemVer 的 `^` 范围（如 `^1.2.3` 不含 `2.0.0`，`^0.2.3` 不含 `0.3.0`），预发布版须显式选择。若依赖约束没有共同解，构建失败并列出冲突版本及各自依赖路径；改本地简称不能回避冲突。

workspace 锁文件记录完整依赖图、来源、确切版本和发布内容摘要。已有且满足清单的锁应沿用，升级由开发者主动发起。锁定模式（候选名 `--locked`）在缺锁或清单与锁不符时失败，但可以下载锁中指定的包；离线模式（候选名 `--offline`）禁止联网，缺少制品时指出具体的包和版本。库包的锁用于自身开发测试；作为依赖时由最终应用 workspace 的锁决定解析。

锁文件使依赖选择可复现。要得到逐字节相同的产物，还需要固定编译器、目标、linker、编译选项和其他构建输入。

## Workspace、发布和包中心

- workspace 支持在一个本地工程中开发多个包，不自动放宽包的公开 API 规则。
- 把 workspace 的本地依赖切换为发布版本时，只要保留调用方清单中的依赖简称和模块路径，源码 `import` 就不用改。解析来源和内容的变化仍体现在锁中。
- 默认分发带清单的源码包，由使用方工具链编译。
- 发布包不得依赖作者机器上不可发布的本地路径。
- 注册中心内同一包身份和版本一经发布不可覆盖；修复必须发布新版本。
- 注册中心是包版本的来源/索引，不参与解释源代码 `import`。

普通撤回的版本不参与新解析；已有锁精确指向该版本且制品摘要吻合时可继续构建并给出警告。摘要不符不能放行。恶意制品封禁另设策略，不沿用普通撤回的旧锁例外。私有中心、签名、闭源制品、名称保留政策与封禁分发协议后续设计。

## 构建脚本授权

包可以声明所需的构建或安装脚本。普通构建只列出脚本、来源包及版本，并提示用单独的命令执行；即使脚本被声明为必需或以前已获授权也不能自动运行。若缺少它的产物，构建报告缺什么，不擅自补跑。

专用命令在执行前展示脚本、来源和所需权限；授权绑定来源包、版本、脚本内容摘要和权限集，任一变化须重新授权。CI 缺授权就失败；离线模式始终禁止网络。平台无法执行要求的隔离时拒绝运行，脚本失败不发布部分产物。授权存储、平台沙箱和产物摘要格式是实现问题。

为[宏](metaprogramming-data.md#f1-macro-inputs)准备 SQL 快照或协议生成物也遵守这条边界：项目把产物作为只读输入交给指定宏；准备工具获准访问开发库，不等于宏或普通 `build` 获准连库刷新。宏展开所用的输入与包解析所用的锁文件各有用途。

## 已接受验收行为

- 同目录拆分源文件不改变模块路径；跨目录移动会改变模块路径。
- 单纯导入不触发可观察的运行期副作用。
- 私有声明不能跨模块导入；public alias 不能暴露私有类型。
- 两条依赖路径要求同一包身份的不兼容版本时，构建失败并指出两条依赖链。
- 未修改锁文件的构建选择相同的依赖版本、来源和内容摘要。
- 同一普通撤回版本：新解析跳过；已有匹配摘要的锁可构建并警告；替换为不同内容后拒绝构建。
- 发布时拒绝未替换的机器本地依赖；版本不可原位覆盖。
- 普通构建不运行第三方脚本，只有显式授权命令才执行。
- CI 原先只授权读指定目录的脚本，包升级后请求联网；专用命令因缺少新授权失败，普通 `build` 也不会代跑。
