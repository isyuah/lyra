# Lyra RFC：异步执行

**状态：冷 Task、串行域、显式并行与跨域等待、有界阻塞池、任务组收尾与异常展示顺序已接受。**  
**范围：** 异步调用、启动和多次等待、执行域、Context、取消与任务组的收尾责任。

## Cold Task 生命周期

调用 `async fn` 会先构造未启动的 Cold Task。创建时先从左到右求显式实参，再按形参顺序求实际用到的默认值，各一次；函数体要等第一次 `await` 或 `spawn` 激活。每个 Task 最多启动一次。

```text
val work = fetch(nextId())
// nextId 已执行，fetch 函数体尚未执行
val first = await work
val second = await work
// fetch 只执行一次；两次 await 观察同一个终态和值
```

多次等待同一 Task 观察同一次完成、异常或取消，不会重复运行函数体。Struct 结果按值返回，Class 结果共享同一对象身份。`Task<Connection>` 也遵循这条规则：两次 `await` 只打开一次数据库，拿到同一个连接。一方关闭成功后，另一方拿到的是已关闭的连接，不会重新打开或复制 C 句柄。普通 `Task<T>` 不要求 `T: Copy`，也不因返回资源就变成一次性 Task。

直接 `await` 冷 Task 由当前作用域激活并负责收尾；等待已启动的 Task 只观察其终态，不改变哪个作用域负责收尾。被创建后丢弃的未启动 Task 不运行函数体，因而体内的 `defer` 尚未登记；调用实参已经发生的副作用不回滚。

## 执行域与 `spawn`

每个 Task 归属一个串行执行域（Execution Domain）。普通 `spawn` 将子任务加入当前执行域：多个任务可同时处于等待/挂起状态，但同一执行域同一时刻只有一个 Worker 执行用户代码。Task 可在 `await` 挂起之后迁移到另一 Worker 线程恢复；迁移不改变执行域串行语义。

这使不含挂起点的一段同域读改写不会与同域另一个任务同时执行。但任务在 `await` 前后可与其他任务交错，不能把跨挂起点的多步读改写当成原子操作。普通 `spawn` 不要求操作系统创建新线程，也不保证 CPU 并行。

跨执行域并行必须显式开启。普通 Lyra 对象（包括可变 Class、闭包捕获、全局状态和 Context 中的普通引用）可以直接跨域共享，不要求声明 `Send`、`Sync`、深不可变或先包装成同步类型。`val` 只限制绑定，不给对象加锁。

标准库 `parallel { ... }` 在另一执行域启动块，把任务登记到当前任务组，返回已启动的 `Task<T>`。`val work = parallel { compute() }` 后可直接 `await work`，继续执行的位置属于**等待者自己的执行域**，不要求回到同一 Worker。任务归组不随等待者改变。首版原子 API 只提供顺序一致的操作，不要求用户选择内存序。

同步由需要保证结果的一方负责：两个域对同一个初值为 0 的计数器各执行一次 `count += 1` 是合法程序，但可能丢失一次更新。两次更新都持同一把锁，或都使用原子加法，并等待两者结束后，结果必须是 2。**安全代码即使有数据竞争，也不能伪造引用、访问已释放内存或破坏 GC 堆**；这不保证复合操作原子，也不要求运行时自动锁住所有对象。原生库对同时操作同一句柄的限制由其安全封装处理，不改变普通对象的跨域资格。

## Task Group 和错误传播

`spawn` 建立的子任务登记在当前结构化 `TaskGroup`。丢弃其句柄不会解除父作用域的等待、错误观察和清理责任；Task Group 在退出前必须等待所有子任务完成清理。这条规则回答的是「谁等孩子结束」，不限制谁能引用 Task 或结果对象。

当前任务直接 `await` 并首次激活冷 Task 时，子任务的普通异常回到该 `await` 表达式，按普通调用链找 `catch`。被捕获后父任务可以正常继续，组不再重复汇总该次失败，也不因此取消兄弟任务；若未捕获，失败随父任务继续向外传播。再次 `await` 同一 Task 仍能观察到同一异常，前一次捕获不改写子任务的终态。

无人等待的 `spawn` 子任务若发生未处理的普通异常，所属 Task Group 请求取消仍在运行的兄弟任务，等待它们完成清理，然后汇总全部已发生的异常。多个这样的子任务都已抛出异常时，按子任务登记顺序展示，不按完成顺序。若另一组的任务 `await` 已启动的子任务，它可以在本地捕获异常，但不接管原组的报告责任；两组谁先结束等待不影响结果。

普通 `Result::Err` 是一个完成值，不自动触发整组取消；若业务规则要求取消，调用者或组策略应显式转换/处理。主动取消单个子任务默认不连带取消其兄弟。

父作用域取消向子任务传播。长期后台任务须交给明确寿命覆盖它的根任务组/服务监督者，不以丢弃本地句柄作为分离机制。

## Task Context 与取消

Task Context 绑定逻辑 Task，不绑定 Worker 线程。**在首次激活时**从当前作用域捕获 context。子作用域的有效 deadline 是父 deadline 与本地 deadline 中更早的一个，并继承取消和 Trace Context。

若 C 用自己的 deadline 等待 B 组已启动的 Task，C 超时只取消 C 的等待，不改变任务的归组或 Context。B 自身被取消或 deadline 到期时，取消沿 B 的子任务传播。等待尚未启动的 Task 则会由当前等待作用域首次激活它。

取消为独立、协作式的控制效果。内置可取消 I/O 和显式取消检查会响应；不检查取消的 CPU 循环及不支持取消的 C 函数不会凭空停止。普通 `catch Exception` 不吞掉取消。限时操作可以把自己的超时转为可处理结果，不能顺带把外层请求的取消转为成功。任务退出时仍执行[同步清理](errors-and-resources.md)。

## 阻塞函数

同步阻塞 C 调用通过 `blocking { ... }` 进入有界阻塞池；池满时挂起调用任务，不阻塞串行执行域的 Worker，也不临时无限增加线程。如果 C API 没有取消支持，取消调用方等待不等于停止底层 C 函数，Task Group 仍需等安全收尾。

首个实测互操作场景为同步 SQLite 连接、查询和 statement 操作。C 侧句柄以明确的作用域 API 确定性关闭，不依赖 GC；首期不包括 C 新线程反向回调 Lyra 闭包。

## 已接受验收行为

- 冷任务创建会执行一次参数表达式，但不会执行函数体。
- `await`/`spawn` 激活冷任务；同一 Task 永远只启动一次，所有等待者观察同一结果。
- 同域两次等待一次成功打开连接的 Task 得到同一对象；经一个别名关闭后，另一个别名查询会报告已关闭。
- 同一执行域多个 Task 可并发推进，但其语言用户代码绝不同时运行。
- 同域跨 `await` 状态允许交错，不能推断为原子。
- 两个显式并行的域可捕获并修改同一个普通对象；用同一把锁保护读改写后，两次更新都可见。
- 当前组直接 `await` 冷 Task 并捕获其异常：父任务继续，同组兄弟任务正常完成，组成功退出；再次等待仍能捕获相同的原始抛点。去掉 `catch` 后，普通异常沿父调用链只上报一次。
- `spawn` 后丢弃句柄且无人等待：子任务抛异常时，所属组取消仍运行的兄弟任务，等兄弟完成清理后报告该异常。
- B 组 `spawn` 子任务，C 组等待它并捕获异常：C 可正常退出，B 仍按登记顺序汇总该失败一次；无论 C 在 B 退出前还是退出后观察终态，结果相同。
- 先登记 A 再登记 B；即使先观察到 B 抛异常，只要 A 也抛出异常，组诊断仍同时列出 A、B 并按该顺序展示。
- C 的同步阻塞操作不会阻塞异步执行域的 Worker；不能停止的 C 调用仍必须完成后才能收尾。
- 异步运行时错误报告异步调用链，来源位置映射到用户代码。

## 仍开放

- 执行域调度实现、锁和原子 API 的具体方法；首版原子操作的内存序不作为配置项。
- 未启动 Task 被丢弃时捕获状态的回收诊断；运行时是否警告未使用句柄。
- 聚合异常的结构化访问 API。
- 库作者声明阻塞函数的方式及后台服务根组接口。阻塞池的默认容量由 Runtime 原型压测决定，不属于语言契约。
