# 普通异常如何越过 Lyra 调用，而不穿过 C

[错误与资源 RFC](../rfc/errors-and-resources.md)区分普通异常、`Result::Err`、任务取消和致命故障。当前原生编译器使用显式异常槽，包括同步函数、异步状态机、`blocking` 与 `defer`。普通 C 函数的错误仍由其 Lyra 包装显式转换；Task 的成功值和 `LyraException` 由不同的运行时接口读取。

## 同步的最小闭环

内置 `Exception(message: String)` 暴露只读 `message`、`taskFailures` 和 `cleanupFailures`，`exception MissingEntry` 声明可按类型捕获的具名异常。`throw expression` 抛出一个普通异常。catch 按源码顺序先匹配类型，再求值可选的 `if` 过滤条件；条件为假继续检查下一项。`catch { ... }` 兜底，具名绑定只在自己的过滤条件和处理块中可见。处理块内单独的 `throw` 原样重抛。`try` 是表达式：正常路径与 catch 中正常完成的分支需要有相同的目标类型；`throw` 类型为 `Never`。`throws` 是签名上的文档标注，不改变调用约定。

```lyra
exception Closed
fn read(): Int { throw Closed("closed") }
fn main(): Unit {
    val count = try { read() } catch reason: Closed if reason.message == "closed" { 0 }
    print(count)
}
```

私有 Lyra 调用约定在普通函数最后加一个控制效果输出槽：普通异常指针和独立的取消标记。调用方先检查取消，再检查异常，最后才读取返回值。`throw` 展开本函数内应退出的块并跳到最近的处理器；未命中则向调用方写出异常。取消跳过处理器，清理当前函数，向调用方传递标记和清理失败；异步根通过任务组收尾发布。原生只写异常指针的接口使用独立的单指针槽。默认实参、隐式转换、闭包和动态接口遵循同一规则；冷 Task 工厂和 `extern` C 声明保持原签名。

捕获时把当前异常从槽中取出，放在 catch 自己的绑定中，再清空槽。这样处理块可以成功返回，也能抛另一异常；裸 `throw` 传播同一异常而不是创建一个新抛点。未被捕获的普通异常由入口打印并非零退出。原生 `extern` 包装仍只按已声明的 C 签名传参；C 不看到异常槽，不让 `longjmp` 或 C++ 异常穿过回调边界。

## 等待和清理的边界

- **Task 的终态属于 Task。** 成功返回值、普通异常、取消须有不同标记。`await` 已失败的 Task 应让等待者的 LLVM 状态机恢复到普通异常分支，而不是直接终结等待者或把 `void* outcome` 当作成功值加载。取消仍进入取消分支，跳过全部普通 catch。
- **重复或跨组等待。** 保存异常的最初位置和已在任务组汇总的所有失败。为每个等待者添加自己的 `await` 位置时使用独立记录，不改写 Task 缓存的终态、归属或另一等待者的栈。激活模式决定失败走哪条路：直接等待冷 Task 走调用链，捕获后不另行组汇总；未观察的 `spawn` 走组汇总，跨组等待者不接管原组责任。三个可独立验收的场景见[异步 RFC](../rfc/async-execution.md#已接受验收行为)。
- **阻塞工作线程。** 闭包可以同步抛异常，原生工作回调正常返回带标记的完成结果，由执行域发布终态。工作线程不能跳回等待者的 native stack，线程局部变量也不能代替逻辑 Task 的状态。
- **`defer`。** 每个同步清理回调也要能把异常作为普通 C 返回值交回清理循环。循环在每次调用前弹栈，按逆序继续运行剩余清理。正常完成（包括提前返回 `Err`）时，首个清理失败成为主异常；展开异常或取消时保留原主因，按实际执行顺序附加所有清理失败。取消的附加原因保留在取消结果中，不把取消改造成可被 `catch` 吞掉的普通异常。

异常报告使用 GC 管理的不可变记录：消息、最初 `throw` 位置、普通调用、Task 创建、`await` 位置和附加失败。记录保留异常身份：`catch` 的绑定仍与原异常按身份相等；一个等待者附加调用帧或附加失败不会修改别人的记录。报告遍历不递归使用原生调用栈。文件名和帧标签是编译器保留的静态 C 字符串；异常消息是带显式长度的 Lyra `String`。

## 行为验收

`tests/exceptions_cli.py` 使用真实源码检查或构建 Debug/Release 两档原生程序，`tests/runtime_exceptions.cpp` 检查 GC 后的不可变记录及输出顺序。

1. 让异常跨两个普通函数到达 `try`；处理后继续执行，抛点之后的语句不执行。内层 catch 裸重抛时报告原抛点。
2. 让默认表达式抛异常：之后的默认值和被调函数体都不执行。让转换函数抛异常：不把它改成 `Result::Err`。
3. 正常块尾、显式 `return`、`?` 和已有异常分别触发两个会抛的清理：每个清理都执行且只执行一次，保留主因和所有次因。
4. 分别等待发生普通异常、返回 `Err` 和被取消的任务；只有第一者进入普通 catch。重复等待保留原抛点；忽略已启动子任务的句柄仍能观察组失败。
5. SQLite/native 工作在取消后安全返回，再释放资源；清理失败作为取消的附加原因报告，不越过 C 调用帧。
