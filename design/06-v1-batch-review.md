# Lyra 首版 RFC：集中确认单

本批 16 项已收到集中答复。变长调用此前已定：`...ids` 首版只展开列表，函数体得到独立的 `List<T>`。

**总答复：** 本批 16 项已结清：13 项按原推荐接受，C1、F1 按复核后的推荐接受，H1 委托设计并已形成[编译器与运行时验收方案](../rfc/compiler-acceptance.md)。下文保留各项内容，规范以[专题 RFC](../rfc/README.md)为准。

## A · 语法、调用与控制流

- **A1｜换行、运算符和求值顺序。** 推荐采用 [RFC-0002 §3–4](../rfc/0002-syntax.md) 的表：行首 `.` / `?.` 可接上一行，`price` 下一行的 `+ tax` 不回接；`return` 后直接换行是无值返回。运算符优先级不因导入改变；接收者和操作数从左到右各求值一次，短路跳过的部分不求值。这样格式化不会悄悄改变调用或副作用。
- **A2｜函数值、lambda 与分支。** 推荐函数类型写 `(Int) -> Int`，lambda 写 `(value: Int) => { value + 1 }`；尾部块的 `{` 与调用放同一行。条件只接受 `Bool`，`match` 支持枚举载荷、嵌套模式和 `_`，按源码顺序取首个命中；循环的 `break` 不带返回值。守卫、带标签跳转和自定义迭代协议暂缓。其余词法拼写按原答卷和 RFC-0002 整理，不逐个问标点。

## B · 类型、对象与泛型

- **B1｜几个实参给同一个 `T` 提供了不同类型。** 推荐对整数取能无损容纳各实参类型的最窄共同类型；没有唯一结果就提示显式指定。例如 `choose<T>(a: T, b: T)` 收到 `Int32` 和 `Int64`，取 `Int64`；收到 `User` 和 `Response` 不搜索用户转换来猜 `T`，可以明确写 `choose<Response>(user, response)`。不退回 `Any`。这补的是[多实参推断](../rfc/0003-types.md)，不改已定的单实参规则。
- **B2｜重载还打平时怎么选。** 推荐 `T → T?` 劣于精确匹配、优于用户转换；若它与数值提升竞争则报歧义。同符号整数有多个无损提升时选最窄者。无后缀整数字面量优先 `Int`；没有 `Int` 候选时，只选唯一能容纳该值的目标。已有规则仍打平时，优先固定参数，再选少用默认值的；仍并列就报歧义、列候选。例：`f(Int)` 和 `f(Int...)` 对 `f(1)` 选前者。
- **B3｜对象与接口的首版写法。** 推荐简单构造写 `class Badge(val title: String)`；复杂初始化仍可写显式构造器。异构集合用显式接口值，如 `List<dyn Render>`，转换时由编译器检查所需成员；普通 `draw<T: Render>` 保持静态调用。可写的 `List<Badge>` 不能当作 `List<dyn Render>`，否则就能往徽章列表里塞入别的类型。关联类型、用户指定特化和通用字段反射后置。见[泛型与接口](../rfc/generics-and-interfaces.md)。

## C · 错误、取消边界与资源

- **C1｜业务错误与异常（已接受）。** [`?` 与普通调用共用无名 `implicit`](../rfc/errors-and-resources.md#c1-conversions)，不设第二种自动转换；仅适用于某个调用点时显式映射。异常根名 `Exception`，普通异常可兜底捕获、原样重抛，`throws` 只作文档提示。
- **C2｜文件或连接被再次关闭。** 推荐已关闭时再调 `close()` 直接成功。若读写仍在使用句柄，本次关闭抛出 `Busy` 清理异常，句柄保持打开；若另一个调用者已开始关闭，本次也报 `Busy`，只有先开始的调用者释放句柄。例如请求取消时 SQLite 还在读：先等隔离操作安全返回，再由登记的 `defer` 关闭，不阻塞调度线程。

## D · 异步执行与并行

- **D1｜显式并行与跨域等待。** 推荐标准库函数 `parallel { ... }` 在另一执行域启动工作，返回已登记到当前任务组的 Task。可以直接 `await` 它，恢复在**等待者自己的域**。其他组来等待时，超时只结束该次等待；所属组取消时仍会取消子任务。共享普通对象照旧，需要确定更新结果时用同一把锁或原子操作；首版原子 API 只提供顺序一致的操作。见[异步执行](../rfc/async-execution.md)。
- **D2｜创建、阻塞和多任务失败。** 推荐 `async fn` 缺省参数与显式参数一样在创建 Task 时求值，函数体仍是冷的。`blocking { ... }` 走有界阻塞池，池满时挂起调用任务；已经开始且无法中断的 C 调用按现有清理约定收尾。多个子任务都抛出未处理异常时，全部保留，按子任务登记顺序展示；普通 `Err` 仍是返回值。后台服务使用有明确寿命的根组，不新增自由脱离的关键字。

## E · 模块、包与构建

- **E1｜解析、升级和撤回。** [模块路径、可见性、单版本解析和源码包](../rfc/modules-packages.md)已定，JSON5 清单字段也已委托设计。推荐首版支持精确版本和 SemVer 的 `^` 范围，预发布版显式选择。普通撤回的版本不供新解析选取，但已有锁且内容摘要吻合时仍可构建并给警告；恶意制品封禁与普通撤回分开。删除公开名称或 re-export 按破坏性 API 变更处理。无需你填写锁文件结构或包中心网络协议。
- **E2｜脚本授权何时失效。** 推荐授权绑定来源、版本、脚本内容摘要和所需权限；任一变化需重新授权。普通 `build` 仍不执行脚本；专用命令在 CI 缺授权时失败，离线模式不给网络，失败的脚本不发布半成品。若当前平台无法提供脚本声称需要的隔离，明确失败，不把它当作已隔离执行。

## F · 宏、HTTP 与数据交换

- **F1｜路由和 SQL 查询所需的宏能力（已接受）。** [声明宏与表达式宏](../rfc/metaprogramming-data.md#f1-macro-inputs)可以读取传入的语法和项目指定的只读输入。普通编译使用查询快照；准备快照或在线检查由显式授权的工具执行，不给宏任意宿主权限。路由适配器仍调用受 `@trace` 装饰的原业务函数。
- **F2｜外部数据的默认策略。** 推荐 JSON/TOML 只自动映射公开字段；遇到未知键默认报错并给出字段路径，允许接口显式选择忽略。普通可空字段的 `None` 默认省略；若省略会被读成非空默认值，JSON 写 `null`。嵌套可空沿用[缺失 / null / 值的区分](../rfc/metaprogramming-data.md)；格式表达不了某状态就报错或显式定制。TOML 也用 `#derive(Toml)` 请求生成，已有实现可直接用。

## G · 原生部署与 C ABI

- **G1｜哪个环境算交付成功。** 推荐首个部署目标为 Linux x86-64 / glibc，SQLite 使用系统动态库并列入产物依赖。没指定服务器时，以 Ubuntu 22.04 x86-64 作为拟测试的最低镜像，用对应的目标库构建。WSL 是开发环境；若实际服务器是 ARM64、较老发行版或必须用空镜像，只需写这一项例外。现在不用安装 LLVM。见[原生工具链](../rfc/native-toolchain.md)。
- **G2｜首版能直接绑定哪些 C 接口。** 推荐先支持显式 `extern` 声明、C 标量、指针与不透明句柄；字符串按 C API 明确传长度或终止符，读取 SQLite 文本时在底层缓冲失效前复制回 Lyra。首个绑定做成按需导入的官方 SQLite 包。C 保存 Lyra 闭包、外部线程回调和任意头文件自动导入后置；业务代码只面对普通对象和 `Result`。

## H · 编译器、GC、诊断与测试

- **H1｜用什么切片结束纸面设计。** 推荐先做一对验收：`check` 在 `fn total(): Int { 1 + 2; }` 的 `;` 处指出实际是 `Unit`；去掉分号，用 `fn main(): Unit { print(total()) }` 调用，经 LLVM AOT 编译的程序独立运行并输出 `3`。接着验证 GC 引用跨 `await` 存活，再跑 SQLite 小服务。异步入口可返回 `Result`，如样例的 `async fn main(): Result<Unit, HttpError>`；入口返回 `Err` 时打印原因并以非零状态退出。工具先做 `check/build/test` 和能指回源码的异步调用栈，`fmt/doc` 和编辑器集成后置。

## 后续如何验收

**其余细节怎么收口。** 错误文案、构造器等文法细表、模块清单字段和命令名，由我按已选行为写成规范和正反例供审阅，不变成新的作者必答题。具体 LLVM 版本、IR 形态、GC 供应商、安全点与根追踪、装箱布局、线程池大小和增量缓存交给工具链原型：用优化构建的存活测试、取消时的句柄测试、与 Go 同负载的多进程内存对照取得证据。先复用成熟 GC、长期做精确根追踪的路线不再投票。完整反射、签名与私有包中心等长期能力保留在对应专题，不阻塞首版。

**本轮问卷结束。** 下一步用[首个编译器切片的测试输入](../rfc/compiler-acceptance.md)先验收 `check` 的源码诊断，再验收 LLVM AOT 产物；[代表服务的四条路径](../examples/user-service/README.md)留给包含异步和 FFI 的后续切片。只有原型暴露出会改变源码写法、程序结果或部署承诺的冲突，才重开对应条目。
